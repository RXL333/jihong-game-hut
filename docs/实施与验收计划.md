# 鸡泓的游戏小屋实施与验收计划

## 已确认的设计

- 沿用已通过的橘色狸花猫、焦糖棕腊肠狗形象，初次二选一并起名。
- 细腻手绘、柔软毛绒质感，手机优先并适配电脑。
- 饱腹度与饮水值均为 0—100；0 表示饥饿或口渴，100 表示吃饱或喝足。
- 免登录，存档保存在当前浏览器；提供导出与导入备份。
- GitHub Pages 纯静态部署，支持仓库子路径。
- 游戏展示采用 Masonry 瀑布流，手机常规宽度双列、小屏单列；各游戏封面采用不同高宽比。
- 全站导航、卡片、面板、按钮和弹窗接入现成 LiquidGlassJS 毛玻璃材质，不自行实现光学引擎。
- 游戏对外名称统一为“羊了个羊”和“合成大西瓜”，保留原技术标识与原始仓库来源。
- 毛玻璃去掉材质底色，仅保留透明模糊、高光和边缘。
- 每只宠物 20 个图片逐帧动作：5 个基础动作，Lv.2—16 每级解锁 1 个；好感不因离线下降。
- 养成节奏约一个月的活跃游玩，饱腹与饮水自然下降但宠物不会死亡。

## 实施顺序与依赖

1. 制作逐帧宠物图集、小屋背景与配乐资产。
2. 实现独立的时间、经验、每日供给、背包、任务奖励与存档逻辑。
3. 制作领养、首页、游戏、背包、动作图鉴、设置及备份界面。
4. 固定三款现有小游戏版本，同源嵌入并接入真实成绩回传；统一协议预留后续游戏扩展。
5. 完成生产构建、单元与集成测试、桌面和手机视口的浏览器验收。
6. 交付可发布静态目录、源码、启动方式、GitHub Pages 工作流和诚实测试报告。

## 验收条件

- 领养、改名、刷新恢复，以及第二个浏览器标签页的存档更新正常。
- 饱腹与饮水方向正确、边界不溢出；离线时间不扣好感；每日边界按北京时间计算。
- 每日补给、60 点好感经验上限、升级与动作解锁、物资消耗可验证。
- 真实游戏事件可产生待领任务奖励，领取只发一次；错误来源、错误会话、重复事件被拒绝或去重。
- 20 个动作各有连续图片帧，图鉴锁定规则与当前等级一致。
- 暂停、减少动态效果、音乐开关、导入校验和导出备份可用。
- 检查 390×844、375×667、320×568、横屏和桌面布局，避免遮挡关键按钮与横向溢出。
- 检查 GitHub Pages 子路径的应用、小游戏及素材地址。
- 测试报告区分已通过、失败和未执行的真机项目。

## 工作边界

当前在本地完成与验证，不修改原小游戏仓库或自动公开发布。小游戏以可重复构建的集成副本接入，保留原始来源。后续正式发布使用项目自带 GitHub Pages 工作流。
