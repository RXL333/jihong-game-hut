# 接入新游戏

小屋使用静态网页与统一成绩消息，不需要后端。建议把新游戏的构建结果放在 `public/games/唯一标识/`。

## 1. 登记游戏

在 `src/data/games.ts` 的 `GAMES` 中加入：

```ts
{
  id: 'new-game',
  title: '你的新游戏',
  subtitle: '一句温柔的介绍',
  category: '游戏类型',
  orientation: 'portrait',
  color: '#dde4c7',
  icon: 'game',
  path: 'games/new-game/index.html',
  originalUrl: 'https://你的原始地址/',
  cover: 'games/new-game/cover.webp',
  missions: [{
    id: 'first-goal',
    title: '小小新收获',
    detail: '单局达到 100 分',
    kind: 'basic',
    metric: 'score',
    operator: 'gte',
    target: 100,
    reward: { snack: 1, feast: 0, water: 1 }
  }]
}
```

`kind`：`basic` 为每天三款合计最多 3 份的基础任务；`advanced` 为每款游戏每日 1 份；`once` 为首次成就。
`operator` 支持 `gte`（大于等于）和 `eq`（相等）。
需要额外条件时添加 `requires: { metric: 'completed', value: true }`。
物品字段始终包含 `snack`、`feast`、`water` 三个非负整数。

加入后，游戏入口、背包成就、奖励判断会读取同一个登记表。瀑布流自动排布，不必修改布局引擎。

入口必须写到 `index.html` 文件，不能只填目录。Vite 开发预览可能把目录地址回退成小屋首页，造成游戏一直等待连接。游戏构建时使用相对资源路径（Vite 的 `--base=./`），以兼容本地预览和 GitHub Pages 的仓库子目录。

## 2. 在游戏中加入 SDK

将 `public/sdk/jihong-hub.js` 和相应 `.d.ts` 复制到新游戏源码中并导入：

```ts
import { createHubBridge, newRoundId } from './jihong-hub.js';

const hub = createHubBridge({
  gameId: 'new-game',
  onPause: () => pauseGame(),
  onResume: () => resumeGame(),
});

// 新开一局才生成新编号；刷新续局必须沿用存档中的编号。
let roundId = savedRoundId || newRoundId('new-game');
hub.startRound(roundId);

// 在真实得分或结算回调中报告，不能用页面打开或计时替代成绩。
hub.report(roundId, {
  score: actualScore,
  completed: actualCompleted,
});
```

`pauseGame`、`resumeGame`、`actualScore` 等是示例中的游戏自身函数或状态。
SDK 在独立打开游戏时保持关闭；被小屋同源嵌入且带合法会话参数时才启用。

## 3. 协议

小屋自动给 iframe URL 添加 `hubSession` 和 `hubOrigin`。
消息字段为：

```ts
{
  channel: 'jihong-game-hub',
  version: 1,
  type: 'ready' | 'result',
  gameId,
  sessionId,
  roundId,
  metrics: { score: 100, completed: false }
}
```

`metrics` 的值只能是非负有限数值或布尔值。
`roundId` 为最多 120 字符的英文字母、数字、点、下划线、冒号或连字符。
小屋同时检查来源窗口、域名、会话、游戏标识和字段类型；发送时使用精确 origin。
按 `gameId + roundId + missionId` 去重，奖励先进入待领列表，玩家收下后才增加背包物资。

纯客户端存档与成绩用于个人休闲养成，不提供服务器级排行榜验证。

## 4. 适配与验收

- 所有资源使用相对路径，检查 `/仓库名/games/new-game/`。
- iframe 内不要注册覆盖整个小屋的 Service Worker。
- 在真实成绩回调中验证达标、重复回传、刷新续局和领取后再次回传。
- 返回小屋和页面进入后台时暂停；关闭目标侧栏时按游戏自身规则恢复。
- 真机检查触控、横竖屏、声音和长时间游玩。
